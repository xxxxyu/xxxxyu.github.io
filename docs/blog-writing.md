# Blog 写作约定

本文集中维护博客的写作与编辑要求。项目级操作规则见
[AGENTS.md](../AGENTS.md)；翻译元数据、系列结构和媒体处理分别沿用
[多语言约定](multilingual.md)、[系列约定](post-series.md)和
[资源工作流](assets-and-galleries.md)。

## 写作与编辑

- 中英文改写优先与本地 Claude 协作；Codex 负责分发、事实核对、网站整合与验收。
  记录实际使用的模型，不把某个模型版本固定为长期要求。
- 文章应能直接阅读，保持作者的论点、判断和语气。改编已有稿件时以轻改为主，
  不无故重写成综述或论文摘要。
- 中文使用相对书面、自然、具体的表达，不为了显得自然而过度口语化。
  英文同样直接清楚。避免套话、机械排比、刻意金句和反复的对照句式。
- 正文应独立讲清问题、方法、关键结果和取舍；补充细节可以放脚注，
  不把理解主线所必需的信息藏在边栏。

## 目录名与标题

- 文章目录采用简短、可读的英文 kebab-case，通常为“项目名 + 主题”，
  如 `oxygen-mot-vla-inference`、`vec-lut-parallel-low-bit-llm`、
  `steerdistill-agent-quantization`。版本发布类文章可采用“项目名 + 版本”，
  如 `cosmos-lite-v030`。不要直接把整句标题变成目录名。
- 中英文文件放在同一个文章目录，图片目录按文章 slug 命名。
  调整未发布文章的 slug 时，同步资源路径、news、论文列表等站内入口；
  已发布文章优先保持 URL 稳定，必要迁移时保留旧地址跳转。
- 文章标题准确表达主题；正文小标题概括该节内容，避免把整段提问放进目录。
  参考近期 posts，在左侧目录可见的桌面宽度下检查中英文标题均保持单行。
  通过精简措辞处理，不为单篇文章缩小字号、裁切标题或另写样式。

## 正文链接与脚注

按链接在句子中的用途区分，而非按 URL 类型区分：

- **正文链接**用于直接访问的入口，例如文首的论文／代码／项目页、模型下载、
  操作指南、issue／PR、页内导航，以及阅读推荐中的原文。
- **脚注**用于文献出处、论据和确有价值的补充解释；来源链接放在脚注中。
  方法名链接代码、旁边脚注引用论文可以同时存在。
- 脚注只有在提供必要出处或额外信息时才保留。相邻的同类参考可合并，
  正文已讲清的内容不再重复；不设脚注数量目标。
- 正面说明必要的条件和统计口径，避免堆砌“并非／不等于／不代表”式防御性表达。
  仅重复文首入口、没有实质补充的“详见主页”也应删去。
- 使用现有 Markdown 脚注 `[^1]`，按首次出现顺序编号，定义放文末。
  桌面边栏和移动端文末显示由站点处理，不另写 HTML。

## 来源、署名与实验结果

- 改编外部文章时，在文首简短说明来源与实际改写模型。例如：
  `本文由 Claude Opus 5.5 根据[知乎原文](原文地址)改写。`
  英文可用 `Adapted by Claude Opus 5.5 from the [original Zhihu post](source URL).`
  模型名按实际情况填写，链接文字不必重复原文长标题。
- 改写署名与翻译元数据分别记录；翻译字段遵循[多语言约定](multilingual.md)。
- 核对数据的具体设置、指标与版本，再更新正文、表格和差值。
  工作区修订稿、rebuttal 记录与公开论文的内容可能不同；引用“论文附录／表格”
  前确认公开链接中确实存在对应内容。内部材料可用于核对，读者引用应指向
  可访问的来源；未公开结果直接说明实验设置与结果，不虚构公开论文指引。
- 区分主结果与补充实验、成功率与多指标均分、训练耗时与推理指标。
  必要说明应简短具体，不用大段免责声明代替准确陈述。

## 图片与表格

- 复用网站现有模板、shortcode 和排版。配图应服务于论述，不为单篇文章默认
  增加专用前端、交互组件或动效。
- 案例和方法图可直接使用清晰的论文截图，沿用 `image` shortcode，提供
  有用的 alt 和简短图注。保留来源、版本和第三方署名；授权规则见
  [LICENSE.md](../LICENSE.md)。具体资源处理见[资源工作流](assets-and-galleries.md)。
- 实验对比优先使用 Markdown 表格。图片与表格采用不同版本的数据时，
  在图注或相邻正文中准确注明版本。

## 双语与验收

- 中英文的事实、数值、链接用途和脚注位置保持一致，措辞可按各自语言调整。
  链接 URL 及出现次数、脚注编号及引用次数、标题层级、表格数据、图片路径
  和关键元数据应符合仓库的双语检查。
- 按项目规则运行相关检查和生产构建；检查正文链接、脚注和目录跳转，
  以及桌面、窄屏下的图片与表格。不要手工修改 `public/`。
